# Portfolio

A full-stack portfolio web application built with ASP.NET Core, designed to showcase professional projects, technical skills, work experience, and provide a secure contact and administration system.

The project was developed as a practical implementation of layered architecture, containerization, relational databases, authentication, continuous integration, and self-hosted deployment.

## Overview

The application provides a public portfolio website and a protected administration panel for managing its content.

Main features include:

* Project portfolio management
* Skills and professional experience sections
* Contact form with spam protection
* Secure administration panel
* Message management
* Pagination for administrative views
* Global error handling and structured logging
* Health checks for the application and database
* PostgreSQL persistence
* Docker-based deployment
* Automated build and test validation with GitHub Actions

## Architecture

The solution follows a layered architecture with separation of responsibilities:

```text
Portfolio.Domain
    Core entities and domain rules

Portfolio.Application
    Application contracts, use cases, and business logic

Portfolio.Infrastructure
    Entity Framework Core, persistence, Identity, and external implementations

Portfolio.Web
    ASP.NET Core MVC presentation layer

Portfolio.Migrations.Sqlite
    SQLite migrations for local development

Portfolio.Migrations.PostgreSql
    PostgreSQL migrations for production
```

Dependency flow:

```text
Web
├── Application
└── Infrastructure

Infrastructure
├── Application
└── Domain

Application
└── Domain
```

## Security

The application currently includes:

* ASP.NET Core Identity authentication
* Secure authentication cookies
* Non-persistent administrator sessions
* HTTPS support
* Forwarded header processing
* Contact form rate limiting
* Honeypot spam protection
* Minimum form completion time
* Global exception handling
* Environment-based secrets
* SSH key authentication on the deployment server
* Firewall-restricted server access
* Private administration through Tailscale
* PostgreSQL isolated from public network access

Additional security hardening is planned, including administrator login rate limiting, account lockout policies, documented security testing, and optional restriction of the administration area to the private Tailscale network.

## Deployment Architecture

The application is self-hosted on an Ubuntu Server virtual machine running in Proxmox VE.

```text
Internet
    |
    | HTTPS
    v
Tailscale Funnel
    |
    | Local proxy
    v
Caddy
    |
    | Docker internal network
    v
ASP.NET Core
    |
    v
PostgreSQL
```

Administrative access to the server is performed privately through Tailscale and SSH key authentication. Proxmox, SSH, PostgreSQL, and the Docker daemon are not exposed directly to the public Internet.

The deployment includes:

* Automatic VM startup
* Automatic Docker service startup
* Container restart policies
* PostgreSQL persistent volumes
* Application and database health checks
* PostgreSQL backup and restore verification
* Recovery testing after VM and Proxmox host restarts

## Local Development

### Requirements

* .NET 10 SDK
* Docker and Docker Compose
* Git

### Clone the repository

```bash
git clone https://github.com/AndrelGanShiTV/portfolio-csharp.git
cd portfolio-csharp
```

### Configure local environment variables

Copy the example environment file:

```bash
cp .env.example .env
```

Update the values in `.env`:

```dotenv
POSTGRES_DB=portfolio
POSTGRES_USER=portfolio_user
POSTGRES_PASSWORD=replace-with-a-secure-password

ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=replace-with-a-secure-password
```

The administrator password must satisfy the configured ASP.NET Core Identity password policy.

Do not commit the real `.env` file.

### Run with Docker Compose

```bash
docker compose up -d --build
```

Check the service status:

```bash
docker compose ps
```

The application is available locally through Caddy.

```text
https://localhost
```

The local certificate is generated by Caddy and may require manual trust or a temporary browser exception.

### Run without Docker

From the repository root:

```bash
dotnet restore Portfolio.slnx
dotnet build Portfolio.slnx
dotnet test Portfolio.slnx
dotnet run --project src/Portfolio.Web
```

Local execution uses the development database provider configured for the application.

## Production Configuration

Production deployment combines multiple Compose files:

```bash
docker compose \
  --env-file .env.production \
  -f compose.yml \
  -f compose.production.yml \
  -f compose.funnel.yml \
  up -d --build
```

Production secrets are stored in `.env.production`, which must never be committed.

An example is provided in:

```text
.env.production.example
```

## Branching Strategy

The repository follows a development workflow based on:

```text
main
└── develop
    └── feature/*
```

* `main` contains stable releases.
* `develop` contains integrated work for the next release.
* `feature/*` branches contain isolated sprint or feature development.

Completed feature branches are merged into `develop`. Stable releases are promoted through a Pull Request from `develop` to `main`.
